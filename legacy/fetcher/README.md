# Device Inventory Fetcher

The **Fetcher** is the high-performance data engine of the platform. It is a standalone background service written in **TypeScript** (running on **Bun**) that connects to external providers to build a complete inventory picture.

---

## ⚡ Performance & Architecture

### Multi-Phase Sync Strategy
The fetcher executes in optimized phases to handle dependencies and maximize speed:

1.  **Phase 1: Core Identity (Parallel)**
    *   Fetches **All Devices** (Intune) and **All Users** (Entra ID) simultaneously.
    *   Uses **Delta Queries** to retrieve *only* changed records since the last run.
2.  **Phase 2: Enrichment (Parallel)**
    *   **Compliance:** Fetches granular policy states for each device.
    *   **Configuration:** Fetches profile statuses (BitLocker, Firewall, etc.).
    *   **Warranties:** Queries vendor APIs (Lenovo/Dell) using serial numbers from Phase 1.
    *   **App Reliability:** Pulls "App Crash" data from Endpoint Analytics.
3.  **Phase 3: Ingestion**
    *   Normalizes all data and posts it to the `api-ts` service for indexing.

### Concurrency Control
To prevent hitting Microsoft Graph API's `429 Too Many Requests` limits, the fetcher uses a customized `p-limit` implementation. It dynamically manages the number of concurrent requests, ensuring maximum throughput within safe boundaries.

### Dynamic Reloading
The fetcher is "Auto-Provisioning Aware." It listens to **Redis** signals. If the API updates the environment (e.g., rotates a certificate or updates credentials), the fetcher detects the signal and reloads its configuration instantly without needing a container restart.

## 🔐 Authentication

The fetcher supports a prioritized authentication stack:
1.  **PFX Certificate (Recommended):** Uses a secure PKCS#12 certificate file (auto-generated by the wizard).
2.  **PEM Certificate:** Legacy support for standard crt/key pairs.
3.  **Client Secret:** Fallback for development (least secure).

## 🛠️ Setup & Usage

### Prerequisites
*   **Bun** Runtime.
*   Access to the **API Service** (for ingestion).

### Installation
```bash
cd typescript
bun install
```

### Running Locally
To perform a single, one-off sync:
```bash
bun run src/index.ts
```

### Running in Docker (Production)
The Docker container runs a **cron scheduler** (`supercronic`).
*   **Default Schedule:** Every 30 minutes (`*/30 * * * *`).
*   **Override:** Set the `CRON_SCHEDULE` environment variable.

### Force Sync (Docker)
To manually trigger a sync inside the running container:
```bash
docker exec -it device_inventory_fetcher /app/run-and-ingest.sh
```

---

## 📁 Data Storage

*   **Temporary Data:** JSON files are generated in `/data` before ingestion.
*   **Delta Tokens:** Stored in `/data/.delta-state` to persist sync progress across restarts.
*   **Logs:** Execution logs are written to `/data/logs`.
